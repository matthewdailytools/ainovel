# 分层内容扫描

扫描用于发现可以回到原文核实、处理的问题。流程是“明确本次检查项与覆盖 → 检索或阅读取证 → 核对语境与例外 → 按影响给最小修法”。修订和训练另走工作流程，不因扫描发现问题就自动改稿。

## 1. 输入与覆盖

记录正文目标和可获得的版本、实际检查范围、作者关注点、固定条件、可用前文及所用词表。无版本系统时说明是“用户本次提供文本”；不要编造版本号。

只启用用户请求或本次已选中的检查项；缺少与本次目标无关的资料不作为问题。必要上下文只用于取证，不因此扩大修改范围。

- 只给一段：完成本段可读性与词语检查；跨章事实未核验。
- 没给词表：词表检查记为未执行；若同时请求一般写作诊断，继续该部分。只请求词表扫描时不擅自扩为全章体检，不凭模型记忆生成平台禁词表。
- 内容过长：按章／场景分段，保留必要相邻语境，登记已检查及未检查范围。跨片段矛盾需要两侧原文，汇总摘要仅用于导航。
- 资料有冲突：先标明来源及版本，不把计划、旧稿、传闻和本版正式事实混为一谈。

## 2. 词语扫描

### 2.1 词表的四类含义

| 类别 | 规则来源与用途 | 命中后如何处理 |
| --- | --- | --- |
| 作者硬性禁用 | 作者明确不希望当前范围出现的词句 | 逐字出现是词表命中；是否违反规则仍核对适用范围和例外 |
| 表达提醒 | 作者想减少的口头禅、套话或特定修辞 | 返回位置、分布及具体重复效果，不因出现一次就判错 |
| 专名与用词规范 | 已采用的人名、地名、术语和写法 | 对照主名、别称、语境与人物故意误称；不能自动统一所有变体 |
| 外部发布规则 | 用户提供或任务授权核实的特定平台规则与适用日期 | 只按可核实范围提示；未配置、规则过期或无法确认时明确标记 |

没有上述第四类来源时，不输出“平台审核通过”或“未发现敏感内容”等扩大结论。内容语义检查也不等于法律或发布合规认证。

### 2.2 可复用的词表描述

按需要记录：词条、类别、来源、适用范围、匹配方式、是否区分大小写、例外、建议处理、版本／适用日期。不是要求作者每次填完整表单；可从其明确请求提取。

默认按给定字面精确匹配；若作者要“独立词”“忽略大小写”“繁简同查”或变体匹配，单独说明实际采用方式。中文没有天然的空格词界，不能声称子串命中等于独立词命中。默认不把词条当正则。

示例词表，仅作样例，不构成默认禁词：

| 词条 | 类别 | 匹配与范围 | 例外或处理 |
| --- | --- | --- | --- |
| 紫晶令 | 作者硬性禁用 | 本次选区，字面匹配 | 作者在本场景禁用；先标记再给保留情节的替代表达 |
| 不由得 | 表达提醒 | 当前章，字面匹配 | 看是否重复削弱主动性；不直接删除每处命中 |
| 林洲 | 专名与用词规范 | 当前章，字面匹配 | 主名为“林舟”，但对白故意叫错时保留 |

### 2.3 匹配与定位约定

- 可用确定性逐字检索时优先使用；报告所用工具及扫描文件范围。只有模型阅读时标为人工语义／词语筛查，不宣称穷尽全部命中。
- 先保留原文，再做获准的规范化；转换后的命中要映射回原文。不能直接使用去空格、繁简转换后的位置修改原稿。
- 区分命中总次数、命中词条数、被例外排除数和有效待处理数。统计不完整时不提供精确总数。
- 单个位置可同时命中多个词条；合并展示时保留规则来源，避免数量重复计算。
- 词频异常需结合作者设定的观察范围；本章重复不自动等于全书口头禅。允许修辞复沓、对白特征和必要术语重复。
- 用原文段落号和短引文定位即可；只有工具返回或可靠计算时才给字符范围。前端 UTF-16 偏移不能直接当 Python 字符下标，存在 emoji 等字符时尤其如此。
- 逐字匹配漏掉的拆字、谐音、变体可列为另一次语义检查目标，不冒充精确匹配已覆盖。不要擅自扩展到所有可能变体。

## 3. 分层扫描索引

S01—S11 为正文问题的检查维度，S12 保留为覆盖限制的兼容编号，不生成正文缺陷。整体体检先按当前范围巡视这些维度，再仅为有信号的主题加载对应写作层；专项请求只处理指定主题及必要依赖。

| 扫描项 | 检查对象与证据 | 相关能力 |
| --- | --- | --- |
| S01 词语、专名与用词规范 | 正文命中、适用词表、例外；有意误称与无意错名分开 | B01、B05 |
| S02 句法、标点、指代 | 歧义所在句与必要相邻句；不凭非标准语体判错 | B02—B06 |
| S03 空泛、重复与说明负担 | 重复表达的具体信息及其作用；关键动作与解释的分配 | B07、B08、B14、B24；T16、T17 |
| S04 视角与人物所知 | 所选视角、人物获知路径、当前叙述原文 | B15、B16；T19、T24 |
| S05 人物动机、声音与关系 | 行动目的、触发条件、前后表达及已发生关系变化 | B11、B12、B17—B19；T05—T09、T11 |
| S06 时间、空间与动作 | 两侧时间锚点、位置、路程及关键动作顺序 | B09、B21、B26；T13、T24、T26 |
| S07 能力、资源与世界规则 | 已采用规则、获得与消耗、伤势变化及本段使用 | B20、B22、B23；T26、T29 |
| S08 因果、铺垫与反转 | 成败条件、前文依据及新信息改变的解释 | B20、B23；T18、T20、T21 |
| S09 节奏、信息与情绪 | 当前场景作用、信息揭示顺序及情绪转折诱因 | B10、B13、B24、B25；T02、T10、T12、T17 |
| S10 伏笔、承诺与章节结构 | 约定回收时点、已写范围、线索及收束证据 | B26、B27；T20、T22、T23、T25、T36 |
| S11 作者约定与题材预期 | 作者固定原话、采用配置、本段内容；默认偏好不视为锁定 | B28；T02、T30 |
| S12 覆盖限制（非正文问题） | 缺失前文、过期设定、部分扫描、来源不可定位 | 在覆盖记录中说明，不进入待修订问题列表 |

S01—S03 通常从 L1 开始；S04—S05 从 L2 开始；S06—S10 根据当前动作或跨章依赖选择 L2／L3；S11 核对 L0 作者约定。L4 只在相关类型场景出现且服务当前目标时展开。作者只查 S01 时，不附带全章结构改写。

按依赖找根因：例如“对白不自然”若由认知越界造成，先说明认知问题，语言修饰无法消除根因。一个根因关联多项 B/T 编号仍记录为一个问题；重复症状可列位置，不人为扩大问题总数。

## 4. 问题记录

使用三个独立维度，避免把“确定存在一个词”误解成“确定有严重问题”：

1. **性质：** 可确认问题／待核实／审美建议。可确认问题包括有依据的规则冲突或明确语言歧义，不限于情节冲突。
2. **依据：** 逐字命中／已采用规则核对／语义判断；用文字说明确定与不确定之处。
3. **影响：** 是否改变固定结果、破坏当前理解、造成局部歧义，或只是可选表达优化。处理先后取决于影响，不强行给每项打数值分。

建议记录：问题编号、目标及基线、位置与原文、扫描项、性质、依据与限制、影响、最小修法、关联 B/T 编号、处理状态。不要机械输出所有空字段；当前环境没有的元数据保持未知。

跨章矛盾要提供两侧证据。没有必要上下文或只有模型印象时，给待核实提示。问题可确认但引文重复时，保留问题性质，另用段落和上下文消歧；定位是否唯一与问题是否成立分别判断。没有可靠唯一定位就不能生成可应用补丁。一个问题可关联多项能力，但不重复计算成多个独立缺陷。

## 5. 交付与处理

先给检查范围、实际覆盖和本次相关的未执行项，再给有证据的问题。按对固定条件、理解和推进的影响排序；词表提醒与审美建议不自动优先。问题多时合并同类项并保留位置，标明是代表项还是完整枚举，不编造精确总数。

S12 单独列为覆盖记录，例如“未提供第一章，无法核实人物此前是否获知秘密”；这不是“正文存在认知错误”。无发现时只说明所读范围、规则与检查方法下未发现问题。

作者保留的偏好不在同一基线上反复催改；确认为误报与作者接受当前表达分开记录。原文或相关设定变化后，旧报告转为历史，重新定位及复核。

要改稿时读取[工作流程](workflows.md)的 T34；应用报告流转读取[项目适配](project-integration.md)。扫描格式不是应用 API，不自动取得采纳或保存权限。
