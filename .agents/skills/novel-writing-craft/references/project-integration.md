# ainovel 项目适配

只在本项目的应用接入、保存、报告流转或自动运行任务中读取；这些约束不构成写作能力等级。本 Skill 当前仍是指令资产，未自动接入工作台，普通 API 不会因消息包含本地路径或 Skill 名称就读取文件。

## B28：作者约定的控制条目

从作者已采用的原话及作用范围核对固定结果、禁止项、情绪与方向。情绪与写法倾向不自动变成每章硬要求；AI 推导、计划和临时解释不升级为作者新锁定条件。

项目业务依据为根目录 `BUSINESS_RULES.md`；以实际版本为准。当前业务包括原稿及采纳权、三种创作分工、独立审稿定向修订最多两轮、阶段与整书完成范围分别表达。本文件只说明 Skill 怎样适配，不另行定义这些业务。

## 报告与候选

- `review.chapter` 为本章审稿，`revision.targeted` 处理已选问题；现有 `Finding` 严格接受 `severity`、`chapter`、`quote`、`reason`、`repair`，`severity` 为 `blocker`／`suggestion`。Skill 的层、类别、覆盖记录不能直接塞入该模型。
- 工作台定向修订只接本版保存稿的有效独立审稿来源，正文和故事依据变化则停止；要求原文引文唯一定位且为局部片段。词表扫描、普通对话诊断、手动反馈和选区输出不自动成为该来源。
- 这不限制普通对话按作者明确目标给出修改候选；候选不是有效应用补丁，也不自动保存或采纳。
- 待核实项与审美建议不因模型命中升级为阻断。已确认问题是否阻止流程，继续按既有业务分类与作者裁定处理。

## 版本与应用

读取报告、生成候选和应用候选分别核对目标及基线；过期结果保留历史身份，不显示为当前通过。重复引文先消歧，没有可靠原文范围就只给可读建议，不能套补丁；前端 UTF-16 偏移不等于 Python 字符下标。

阶段批次只核对当前范围的有效完成，允许后续主冲突和未到期承诺保持开放；整书才核对全书闭合。工程检查、模型意见、作者定稿与文学效果分别表达。

后续加载器、扩展问题元数据、本地查词或应用来源适配均需独立实现和验证。本次 Skill 分层不修改应用模型、提示词装配或用户稿件。
