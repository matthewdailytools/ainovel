# 七台云同步验收

## 启用与操作

同步服务采用与作品数据库分离的 SQLite 文件。部署配置通过环境变量提供：

- `AINOVEL_SYNC_DB` 指向仓库外的独立同步数据库。
- `AINOVEL_SYNC_PROVISION_TOKEN` 为管理员开通凭据，至少 32 字符。
- `AINOVEL_SYNC_BROWSER_ORIGINS` 填写允许的独立 Web 来源，多个来源用逗号分隔。
- 本机工作台的 `AINOVEL_OFFLINE_SYNC_ORIGINS` 填写桌面页与独立 Web 允许连接的同步服务 origin，更新后重启工作台。生产环境使用明确的 HTTPS 来源。

```powershell
uv run python -m ainovel.cloud_sync_server --port 8888
```

同步服务管理员向 `POST /api/sync/works/{工作版本编号}/devices` 提交不同的 `device_id`，为每台设备签发凭据。作者可从桌面导出同一个稿件包，导入另一端建立共同基线。桌面在「故事与审阅 → 作品云同步」启用，独立 Web 在已打开作品的「作品云同步」启用。两端分别输入各自的设备凭据后手动同步。凭据只留在当前页面。停用后本地稿件和待确认记录保留。

「停用作品同步」暂停本机连接，设备凭据继续有效。桌面「撤销当前设备凭据」和独立 Web「撤销此设备的云端凭据」需作者另外确认。云端只撤销当前作品绑定的那份凭据。收到回执后清空凭据输入，本机稿件和待同步记录保留。回执中断时可用同一凭据再次确认。恢复同步由管理员签发该设备的新凭据。

选定附件支持按 512 KiB 分片续传、SHA-256 核验和下载校验。单文件上限 64 MiB，未完成的附件不会列入可下载清单。真实双端测试在 Web 上传第二片时注入中断，补传后由桌面下载并逐字节核对。同步服务配置、账本和模型密钥不进入稿件包。

独立同步启动入口对非回环地址强制校验证书和私钥，最低 TLS 1.2。隔离进程使用临时 CA 实测协商 TLS 1.3，拒绝不受信证书、主机名不匹配和明文请求。生产域名和证书轮换、加密卷与备份密钥、账户退出、数据保留和监控仍需实际部署验证。[启动与部署](../../README.md) · [TLS 回归](../../backend/tests/test_cloud_sync_server.py)

同步健康检查只读当前 SQLite 及其所需表、字段和索引结构。移走数据库、换入无效文件，或缺少实际路由使用的结构时，健康检查与受影响的同步请求返回 `503 sync_storage`。隔离 Uvicorn 验收在恢复前先发普通查询和推送，恢复目标仍空闲，随后从原备份恢复并重签，读取就绪状态、原稿及回执和附件。恢复库也可继续写入。原数据库和独立归档的校验值保持一致。同步连接的 SQLite 临时页使用内存。[健康检查回归](../../backend/tests/test_cloud_sync_server.py)

静态加密预检核对数据库目录、现存数据库、WAL／SHM、SQLite 回滚日志、库内附件的存储边界及指定备份目录。Windows 要求固定卷 BitLocker 全部加密且保护开启。当前 Windows 测试权限无法读取加密状态，预检按预期拒绝。Linux 在 WSL2 私有挂载空间实测一次性 ext4／AES-XTS dm-crypt 卷，数据库、活动 WAL／SHM 与独立 SQLite 备份均通过，另给普通备份目录会被拒绝。读回原测试正文和备份后，底层镜像未找到该正文标记。生产卷、密钥恢复、系统交换空间及崩溃转储仍按实际部署验收。[静态加密预检回归](../../backend/tests/test_cloud_sync_storage.py) · [BitLocker 运维](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/operations-guide) · [ext4 超级块](https://www.kernel.org/doc/html/v6.6/filesystems/ext4/super.html)

同步服务可显式传入 `--require-encrypted-storage --backup-dir <现有备份目录>`，在 TLS 配置加载后、SQLite 打开或创建以及监听端口之前执行同一项只读核验。隔离子进程遇到无效 WAL 路径以退出码 `2` 停止，端口无监听，数据库和备份目录未写入。以受控系统卷结果通过后，可创建隔离账本并通过健康检查。受控的备份卷拒绝用例核对了原账本字节。生产验收在目标环境中以实际服务运行身份和存储路径复验。[启动示例](../../README.md#独立云同步服务) · [启动预检回归](../../backend/tests/test_cloud_sync_server.py)

SQLite 回滚日志也经过文件类型、同目录及所在加密卷核验。隔离进程遇到同名目录时以退出码 `2` 结束，未打开监听或建立账本。模拟日志所在卷不可核验时，验证现有账本和日志字节均保留。存储、启动、备份及设备撤销组合 **52 项通过**。[存储预检](../../backend/tests/test_cloud_sync_storage.py) · [启动拒绝](../../backend/tests/test_cloud_sync_server.py)

### 云账本恢复后的重新连接

基线 `0718138` 在两个临时账本上复现过同序异稿和桌面冲突提前写入。旧端游标为 6，云备份恢复到 4，另一设备补齐旧序号后，旧端继续同步并采用了新云稿。另一实验中，旧端游标为 14、恢复点为 11，桌面手动解决写入了云序号 12 并更新本机，最后才返回 `409 sync_cursor`。

当前实现给原账本、在线备份及每次恢复分别标记身份。客户端按工作版本保存绑定，核验后才拉取、推送、处理云端冲突或传输附件。真实恢复库对旧身份或缺少身份的请求返回 `409 sync_ledger_replaced`。作品权限验证仍先于账本身份验证，知道身份不会得到作品权限。暂停、重开和换发同一设备凭据均保留原绑定。Web 更换设备编号也保留同一作品的绑定。

1. 管理员用独立文件执行 `create`、`verify` 和 `restore`，在隔离位置读回采用头、冲突、回执及文件。恢复点内的已知变更或回执仍可用新凭据直接核对。保留原库及原本机副本，便于继续查找恢复点之后的提交。
2. 要读取恢复后的云历史，从共同基线或已核对的恢复点建立独立副本。独立 Web 用不同浏览器配置并导入稿件交换包。桌面用独立 `AINOVEL_DATA_DIR` 启动后导入稿件包。管理员为该工作版本重新签发设备凭据，作者在「作品云同步」启用和拉取。比较正式采用头、历史和引用后再决定后续工作。
3. 旧本机副本继续保存稿件、检查历史与待同步记录。Web 仍可离线打开已有冲突比较、编辑合并草稿和另存；正式提交要通过当前账本校验。需要将恢复点之后的创作带回时，可在两个副本之间逐项核对后作者选择采用。保留原浏览器配置或独立本机备份，以便查看原队列和未知回执。

同步库格式为 2。活动的格式 1 同步库在启动时只增加账本身份记录；已有绑定无法验证起源时，两端保留原记录并要求使用独立副本。格式 1 的独立归档可用对应版本在独立位置核验后，将工作副本交给新版服务生成格式 2 备份。[恢复命令](../../README.md) · [复审验收条件](../../七台创作工作流计划复审.md#p0--云账本恢复后的旧连接保护)
