# 七台云同步验收

## 启用与操作

同步服务采用与作品数据库分离的 SQLite 文件。部署配置通过环境变量提供：

- `AINOVEL_SYNC_DB` 指向仓库外的独立同步数据库。
- `AINOVEL_SYNC_PROVISION_TOKEN` 为管理员开通凭据，至少 32 字符。
- `AINOVEL_SYNC_BROWSER_ORIGINS` 填写允许的独立 Web 来源，多个来源用逗号分隔。
- 本机工作台的 `AINOVEL_OFFLINE_SYNC_ORIGINS` 填写桌面页与独立 Web 允许连接的同步服务 origin，更新后重启工作台。生产环境使用明确的 HTTPS 来源。

```powershell
uv run python -m ainovel.cloud_sync_server --port 8888
```

同步服务管理员向 `POST /api/sync/works/{工作版本编号}/devices` 提交不同的 `device_id`，为每台设备签发凭据。作者可从桌面导出同一个稿件包，导入另一端建立共同基线。桌面在「故事与审阅 → 作品云同步」启用，独立 Web 在已打开作品的「作品云同步」启用。两端分别输入各自的设备凭据后手动同步。凭据只留在当前页面。停用后本地稿件和待确认记录保留。

「停用作品同步」暂停本机连接，设备凭据继续有效。桌面「撤销当前设备凭据」和独立 Web「撤销此设备的云端凭据」需作者另外确认。云端只撤销当前作品绑定的那份凭据。收到回执后清空凭据输入，本机稿件和待同步记录保留。回执中断时可用同一凭据再次确认。恢复同步由管理员签发该设备的新凭据。

## 已验证

- 两份独立 SQLite 工作区通过真实同步协议交换章稿。离线分改同章后均保留，选任一稿作为解决版。推送响应丢失时复用变更标识，后续拉取确认已提交的回执。
- Playwright 启动本机工作台及隔离云服务。只含共同基线的 Web 接回历史后可打开远端原稿。桌面与独立 Web 断网分改同章，重连显示双方与共同依据。选用云端版后两侧旧稿均可查。浏览器恢复历史为新修订后，桌面收到新正文。桌面归档与 Web 改稿并发时，仍可比较两侧，选用归档后旧设备的后续同步不会复活章节。
- 服务端用例验证作品权限、设备撤销、幂等回执、游标及冲突比较。使用 `$env:AINOVEL_SYNC_E2E = '1'` 后执行 `npx playwright test cloud-sync` 可重跑真实双端用例。
- M1 正式立项可从桌面同步至独立 Web。两端离线分别确认后会出现三方比较。选择 Web 版后，桌面写入本机新的正式立项修订，保留云端来源设备和回执。独立 Web 仍可回看两版。用同样环境运行 `npx playwright test project-sync` 可重跑。
- 稿件包可以脱离云端恢复 M1 的采用版、父子关系及竞争旧版。Windows SQLite 和浏览器 IndexedDB 往返用例均核验恢复后的新修订能继续连回原父版本。导入记录标明稿件包来源。
- 桌面保存章稿与 M1 时，同一 SQLite 事务写待发送标记。事务回滚时标记一并撤销。已准备的发送请求持久保存，推送期间又编辑时，下轮仍可发送新增修订。回执丢失不会覆写更新内容。
- 独立 Web 的章稿和 M1 也在保存事务写待发送标记。真实 Chromium 用例在第一次发送时中断，重开后复用原变更 ID，继续编辑的后续修订仍能独立发送。
- 两个独立桌面实例通过云同步接收 M3 正式设定及原文依据。保留同一基线的两端修订，作者可比较后选择。接收端当前立项与设定依据不一致时暂缓采用，独立章稿仍正常同步。采用相符立项后可继续接收该设定。[桌面设定同步测试](../../backend/tests/test_settings_sync.py)
- 真实 Chromium 验证桌面和独立 Web 从共同设定版分别确认后，可比较双方版本和共同依据。采用 Web 版后，桌面通过正式确认流程接收，独立 Web 仍可查看竞争版。Web 保存设定时同一事务写版本、采用头和待发送标记。模拟分批拉取验证来源补齐后自动采用，立项及正文来源先于依赖它们的设定发送。[双端设定验收](../../tests/e2e/settings-sync.offline.spec.ts) · [Web 存储测试](../../frontend/settingsLocalSync.test.ts)
- 在新的独立 SQLite 库中，仅凭稿件包恢复 M3 的采用头、父链、竞争旁支、原作者或 AI 来源及包记录的来源设备。恢复时核验包内立项和原稿选区的 SHA-256。立项已换版的旧设定仍可查看并待复核。正文只存为来源历史时，引用仍显示原文，当前数字修订相同也不会被当作同一稿。缺少来源、父链断裂或引文摘要损坏时拒绝整个导入。[稿件包恢复与拒绝测试](../../backend/tests/test_settings_sync.py)
- 真实 Chromium 在断网时首次确认设定并重开修订。稿件包往返桌面后，清空 IndexedDB 并断网恢复，可以从采用版返回父版。恢复记录标明来自交换包。[设定稿件包往返](../../tests/e2e/settings-portability.offline.spec.ts)
- M4 正式大纲已验证桌面与独立 Web 从共同版分开采用。冲突时可浏览两侧及共同大纲，桌面采用 Web 大纲后仍保留已埋设伏笔和原文证据。Web 新建大纲和伏笔初始计划已经验证断网保存与重开。[大纲双端验收](../../tests/e2e/outline-sync.offline.spec.ts) · [本机大纲验收](../../tests/e2e/offline-outline.offline.spec.ts)
- 两个独立桌面工作区通过隔离同步服务交换正式故事记录。本机各改不同记录可分别收敛，改同一记录保留两侧与共同基线。章稿分歧期间暂缓采用引用该原文的实际回收，作者选准章稿后验证全文哈希和 UTF-16 选区再采用。回执丢失只新增一条云端事件。[正式故事记录双端回归](../../backend/tests/test_story_sync.py)
- 桌面和独立 Web 可分别确认同一伏笔的实际进展。浏览器未选保存稿证据时无法提交实际回收。发生分歧后可比较双方和共同依据，桌面选择 Web 版后能回到 Web 回收所用的原文。完整稿件包在独立 Web 恢复相同图谱与大纲，故意移除故事历史时大纲留档待恢复。[浏览器双端及包恢复](../../tests/e2e/outline-sync.offline.spec.ts)
- 历史 M6 体检和 M7 交付按独立对象同步。真实隔离服务先收原章稿，再收体检和绑定该体检的完本记录。桌面和独立 Web 从冻结清单还原材料并逐件校验。正文超过 1 MiB 时，传输的完本对象仍低于 1 MiB，独立 Web 和桌面均还原出原四份材料。超限的清单或体检仍保留本机，章稿继续传输。[历史报告云验收](../../backend/tests/test_workflow_cloud.py) · [独立 Web 大稿件验收](../../tests/e2e/workflow-large-sync.offline.spec.ts) · [独立 Web 来源回读](../../tests/e2e/book-completion.offline.spec.ts)
- M2 按卡片同步正式修订和引用地址，同一会话的不同卡可独立修改。桌面和独立 Web 已实测同一卡的并发确认、共同版本比较及采用后回看两版。隔离云数据只携带手法卡摘要和地址，随包明确选带的原句仍由本机保存。[M2 桌面同步](../../backend/tests/test_reference_cloud.py) · [M2 浏览器比较](../../tests/e2e/reference-archive.offline.spec.ts)
- 独立 Web 可断网把同步收到的正式手法卡挂载进 M4。大纲锁定准确 SHA-256，桌面采用后可回查同一摘要和引用地址。同数字修订存在旁支时按版本解歧，材料原句仍按选带范围留存。[大纲精确引用](../../tests/e2e/outline-sync.offline.spec.ts)
- 章稿同章分歧支持手动编辑合并稿。桌面和 Web 核对比较时的本机与云端基线后创建新修订，保留两份原稿。Web 回执丢失后按原变更编号取回回执，云端只记一次合并。两端也可将选稿另存为新本机工作分支。独立 Web 断网后可从已有比较另存，重开后可核对原稿来源并继续编辑，原分支的冲突仍可处理。停用后可断网新建并保存本机章节。[冲突专项](../../backend/tests/test_chapter_conflicts.py) · [浏览器合并、另存与停用](../../tests/e2e/cloud-sync.offline.spec.ts)
- 两个独立本机库接收含章稿、立项、设定、大纲和伏笔实际进展的卷级回滚。首个拉取页持久化后断开，设备重开从已保存游标续传，双方读到相同正式版本并保留撤回稿。设备凭据撤销后不能再拉取、取回回执或访问附件。本机仍能编辑、从独立稿件包恢复。签发替换凭据后可取回原合并回执并继续传送新改动。[回滚续传、撤销和回执恢复](../../backend/tests/test_sync_recovery.py)
- 真实 Chromium 中断独立 Web 的第二个拉取页。重开后界面读回持久化游标，下一次拉取以该游标继续并得到准确章稿。另一用例在断网另存后导出新分支，清空 IndexedDB，再断网导入，核对最新章稿及另存时的精确原文和 SHA-256。[浏览器断点与离线恢复](../../tests/e2e/cloud-sync.offline.spec.ts)
- 桌面和独立 Web 实测停用与撤销。Web 设备编号和凭据不匹配时拒绝。模拟云端成功但回执中断，重试确认同一撤销，其他设备一直可用。重新签发后原凭据无法撤销新凭据，本机待同步改稿继续发送。[设备撤销回归](../../backend/tests/test_device_exit.py) · [浏览器回执及恢复](../../tests/e2e/cloud-sync.offline.spec.ts)

桌面和独立 Web 已覆盖作品基本信息、分支目录、章稿历史、正式立项、手法卡、设定、大纲、实际故事记录及历史体检和完本。本机修订编号各自连续，跨端证据用原修订 ID 和内容哈希核对。接收时缺少准确依据则显示待处理，原修订到达后可补齐并打开对应正文。超过同步上限时本机保留记录，并显示等待原因。

选定附件支持按 512 KiB 分片续传、SHA-256 核验和下载校验。单文件上限 64 MiB，未完成的附件不会列入可下载清单。真实双端测试在 Web 上传第二片时注入中断，补传后由桌面下载并逐字节核对。同步服务配置、账本和模型密钥不进入稿件包。

独立同步启动入口对非回环地址强制校验证书和私钥，最低 TLS 1.2。隔离进程使用临时 CA 实测协商 TLS 1.3，拒绝不受信证书、主机名不匹配和明文请求。生产域名和证书轮换、加密卷与备份密钥、账户退出、数据保留和监控仍需实际部署验证。[启动与部署](../../README.md) · [TLS 回归](../../backend/tests/test_cloud_sync_server.py)

同步健康检查只读当前 SQLite。移走数据库及换入无效文件时均返回 `503 sync_storage`，响应不含路径且不会创建空库。放回原数据库后返回 `200`。同步连接的 SQLite 临时页使用内存。探针用于识别当前服务是否能读取正确库。[健康检查回归](../../backend/tests/test_cloud_sync_server.py)

静态加密预检核对数据库目录、现存数据库与 WAL／SHM、库内附件的存储边界及指定备份目录。Windows 要求直接固定卷 BitLocker 全部加密且保护开启。Linux 要求直接挂载的 ext4、全设备 AES-XTS dm-crypt 和内部日志，避免外置日志绕过加密边界。自动化覆盖上述组合和拒绝路径。当前 Windows 测试权限无法读取实际加密状态，预检按预期拒绝通过。生产卷和密钥恢复待部署后验收。系统交换空间和崩溃转储由部署环境另行控制。[静态加密预检回归](../../backend/tests/test_cloud_sync_storage.py) · [BitLocker 运维](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/operations-guide) · [ext4 超级块](https://www.kernel.org/doc/html/v6.6/filesystems/ext4/super.html)
