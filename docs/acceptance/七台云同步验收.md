# 七台云同步验收

## 启用与操作

同步服务采用与作品数据库分离的 SQLite 文件。部署配置通过环境变量提供：

- `AINOVEL_SYNC_DB` 指向仓库外的独立同步数据库。
- `AINOVEL_SYNC_PROVISION_TOKEN` 为管理员开通凭据，至少 32 字符。
- `AINOVEL_SYNC_BROWSER_ORIGINS` 填写允许的独立 Web 来源，多个来源用逗号分隔。
- 本机工作台的 `AINOVEL_OFFLINE_SYNC_ORIGINS` 填写桌面页与独立 Web 允许连接的同步服务 origin，更新后重启工作台。生产环境使用明确的 HTTPS 来源。

```powershell
uv run uvicorn ainovel.cloud_sync:sync_app_from_env --factory --host 127.0.0.1 --port 8888
```

同步服务管理员向 `POST /api/sync/works/{工作版本编号}/devices` 提交不同的 `device_id`，为每台设备签发凭据。作者可从桌面导出同一个稿件包，导入另一端建立共同基线。桌面在「故事与审阅 → 作品云同步」启用，独立 Web 在已打开作品的「作品云同步」启用。两端分别输入各自的设备凭据后手动同步。凭据只留在当前页面。停用后本地稿件和待确认记录保留。

## 已验证

- 两份独立 SQLite 工作区通过真实同步协议交换章稿。离线分改同章后均保留，选任一稿作为解决版。推送响应丢失时复用变更标识，后续拉取确认已提交的回执。
- Playwright 启动本机工作台及隔离云服务。只含共同基线的 Web 接回历史后可打开远端原稿。桌面与独立 Web 断网分改同章，重连显示双方与共同依据。选用云端版后两侧旧稿均可查。浏览器恢复历史为新修订后，桌面收到新正文。桌面归档与 Web 改稿并发时，仍可比较两侧，选用归档后旧设备的后续同步不会复活章节。
- 服务端用例验证作品权限、设备撤销、幂等回执、游标及冲突比较。使用 `$env:AINOVEL_SYNC_E2E = '1'` 后执行 `npx playwright test cloud-sync` 可重跑真实双端用例。
- M1 正式立项可从桌面同步至独立 Web。两端离线分别确认后会出现三方比较。选择 Web 版后，桌面写入本机新的正式立项修订，保留云端来源设备和回执。独立 Web 仍可回看两版。用同样环境运行 `npx playwright test project-sync` 可重跑。
- 稿件包可以脱离云端恢复 M1 的采用版、父子关系及竞争旧版。Windows SQLite 和浏览器 IndexedDB 往返用例均核验恢复后的新修订能继续连回原父版本。导入记录标明稿件包来源。
- 桌面保存章稿与 M1 时，同一 SQLite 事务写待发送标记。事务回滚时标记一并撤销。已准备的发送请求持久保存，推送期间又编辑时，下轮仍可发送新增修订。回执丢失不会覆写更新内容。
- 独立 Web 的章稿和 M1 也在保存事务写待发送标记。真实 Chromium 用例在第一次发送时中断，重开后复用原变更 ID，继续编辑的后续修订仍能独立发送。
- 两个独立桌面实例通过云同步接收 M3 正式设定及原文依据。保留同一基线的两端修订，作者可比较后选择。接收端当前立项与设定依据不一致时暂缓采用，独立章稿仍正常同步。采用相符立项后可继续接收该设定。[桌面设定同步测试](../../backend/tests/test_settings_sync.py)

桌面和独立 Web 已覆盖作品基本信息、分支目录、正式立项及其源修订、章稿及其源修订，以及只读随稿依据。正式设定已验证桌面间同步，独立 Web 的设定、大纲和台账的编辑与采用仍待补齐。本机修订编号各自连续，跨端证据用原修订 ID 和内容哈希核对。接收时缺少准确依据则显示待处理，原修订到达后可补齐并打开对应正文。单项超过同步上限仍可通过稿件包或单独选定的附件传递。

选定附件支持按 512 KiB 分片续传、SHA-256 核验和下载校验。单文件上限 64 MiB，未完成的附件不会列入可下载清单。真实双端测试在 Web 上传第二片时注入中断，补传后由桌面下载并逐字节核对。生产 TLS、静态加密、真实网络环境和部署监控未在本轮验证。同步服务配置、账本和模型密钥不进入稿件包。

相关代码和验收见 [隔离云服务](../../backend/ainovel/cloud_sync.py)、[桌面适配](../../backend/ainovel/desktop_sync.py)、[双端测试](../../tests/e2e/cloud-sync.offline.spec.ts)。
