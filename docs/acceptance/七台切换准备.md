## 阶段 0 实测

- 从锁文件离线安装前端依赖并完成类型检查、生产构建。
- 在无头浏览器保存《遗铃》的「门外的遗铃」「归铃」。两个窗口各持第一章修订 1。先提交者成功保存为修订 2，后提交者收到 HTTP 409 并保留本地输入，服务稿没有被覆盖。
- 从版本历史选用修订 1，正式保存为修订 3，修订 2 仍可查。刷新后两章正文保持，最终为修订 3、1。实际生成备份并在空目录恢复，恢复了 1 部作品、2 章和 6 条修订，两章正文与版本逐项一致。
- 主线的构思生成、构思工作台和故障恢复专项共 37 项通过。实测范围为现有产品入口，阶段 0 浏览器样本无生成任务、无模型账目。首轮脚本将编辑器换行当成 DOM 拼接文本，改为按逐行内容断言，失败记录保留。

## 七台的复用落点

| 工作台 | 主线现有基础 | 进入实施时应核对 |
| --- | --- | --- |
| M1 立项 | `ConceptionWorkspace.tsx`、`conception.py` 的分类构思、采用与交接 | 立项卡及可修改结局的确认版本怎样交给设定 |
| M2 拆解 | `ReferenceWorkspace.tsx`、`reference.py` 的资料选段、分析候选和引用 | 手法卡能回溯保存版本，局部重拆后旧引用仍可定位 |
| M3 设定 | `ConceptionWorldExtract.tsx`、`genre_catalog.json`、`story_graph.py` | 混合题材的设定能引用确认立项，区分硬规定、开放项和来源 |
| M4 大纲 | `Workflow.tsx`、`worker.py` 的章纲与任务输入、故事结构记录 | 四级大纲及设定和伏笔计划的确认、引用与失效 |
| M5 写作 | `Writing.tsx`、`domain.py`、`drafts.ts` 的编辑、历史、候选和修订校验 | 接入确认章纲和实际正文证据，保留无立项直接手写及并发保护 |
| M6 校验 | `RevisionPanel.tsx`、`plot_audit.py`、`targeted_revision.py` 的逐项检查和定向复检 | 十处对账各自记录覆盖、稿件版本、原文位置及处理状态 |
| M7 完本 | `manual_finalization.py` 和正文导出 | 六项判定及四件交付物绑定同一版正文和资料 |

阶段 1 先落 M1、M2、M3。以《遗铃》验证作者改结局并确认后，下游读取所确认的版本，手法卡原版仍可回查，空白作品仍能直接手写。后续自动接力沿用任务检查点、版本与费用回执。整书快照、独立 Web 正式离线存储和云同步按阶段 5–7 处理。

样本只验证新建作品。日常稿件、旧任务和真实费用留在原实例。构建、两次无头日志和隔离恢复证据保存在仓库外的 `.ainovel/acceptance/2026-11-18-seven-workbenches-stage0/`。
