# 小说构思结构完整性验收记录

日期：2026-11-14。依据：用户要求构思小说的结构完整，同时沿用简单易用的交互。

## 已实现

「小说构思」仍是一句想法、一个生成按钮，默认给出一个完整方案，不增加必填人物卡、世界百科或逐章表单。

方案包含：一句话故事、读者看点、人物目标与动机、必要背景与关系、核心矛盾、故事主线、关键伏笔回收、结局与人物变化、持续推进或收束方式，以及可调整的AI补充细节。

主线用5至9个规划节点覆盖开端、发展、关键转折、高潮、结局。各节点有具体事件、因果来源、主角选择、结果与代价；后续节点必须承接前一节点。伏笔明确在哪个节点铺设、在哪个节点回收。该范围是本轮结构输出的实现边界，不是所有小说的章节数或固定叙事公式，正文叙述顺序仍可调整。

输入不完整时，模型提出一个可修改的自洽方案和建议结局。开放结局也需交代本书主冲突和人物处境；长篇说明阶段如何产生后续任务，短故事可集中收束。提示词明确保留作者约定，不凭空新增关键能力化解高潮，不自动将建议升级为作者锁定或正文事实。

## 实现与兼容

- 新增动作 `ideation.structure`，版本 `1.0.0`，复用模块队列、账户、共享预算、取消、来源冻结和候选采纳机制；旧 `ideation.explore` 保持原有行为。
- 服务端使用版本化结构契约，检查必要字段、空白与占位内容、结构覆盖、关键阶段顺序、节点编号、前序因果引用、伏笔回收引用及6000字可编辑文本上限。结构错误最多修正一次，仍失败时不发布为完整候选。
- 候选保留生成时的结构、结构版本和修订标记0，后端统一转换为中文可编辑文本。作者修改后的文字不继续冒充原结构检查已通过；界面提示重新核对因果和回收。
- 专用页面的提示词标记升级为 `小说构思工具/2.0.0`，输出Token上限由2048调整为8192，以容纳完整方案；已有账户总预算、价格配置和请求体边界继续生效，没有自动付费评测。
- 历史列表兼容原版与新版工具结果，采用接口同时校验两类动作的候选来源。原工作版本的锁定项及其他契约字段继续保留，不改动正文或生成故事事实。
- 修复新窗口显示原始候选的问题：无本窗口草稿时优先读取作者已采用方向。生成中刷新可继续等待，新生成候选不会误显示成已采用。
- OpenAPI与TypeScript请求类型同步，无新增依赖或数据库迁移；结构保存在既有候选payload中，仍随既有备份保存。

本次没有实现“从新原话中自动确认新锁定项”，也没有宣称完成全部网文适配审阅建议；该事项仍按[网文适配审阅](../../小说构思工具-网文适配审阅.md)单独处理。

## 工程检查

- 构思旧流程与新结构专项：30项检查通过，覆盖正常结构、缺结局、缺发展、空动机、占位结局、断链、未来或重复因果、缺回收、失效或逆向回收、错误转折顺序、超长方案、有限修复成功／失败及采用后保留来源。
- 作者契约、题材继承、新结构与OpenAI结构契约相关回归：136项通过。测试替身已支持新增动作，原有断言保留；新结构加入供应商JSON Schema适配检查。
- API与Worker等其余受影响后端回归已执行，修复新动作的测试替身后，对失败所在文件及结构适配重新验证通过。
- 前端单元：13个文件183项通过。Ruff、Prettier、TypeScript及生产构建通过。
- 浏览器既有方向交接、作者想法到正文及构思工具共9项通过；补充刷新用例后的最终构思专项6项全部通过。构思路径检查包含结构各节、编辑与采用、刷新恢复、新窗口采用稿、失败重试、历史构思、取消与中断片段、无模型直接记录、生成中刷新续看及新候选不误标采用。

## 业务验收与限制

本轮用原创离线样例验证“从一句想法生成包含起因、经过、转折、高潮和结局的结构”，并验证结构缺项或引用断开不会直接成为完整候选。候选仍须作者决定是否采用，作者编辑不被自动改回模型版本。

确定性检查只能保证结构字段与引用关系完整，不能证明人物选择自然、因果描述可信、伏笔回收有力度或作品一定适合市场。真实模型的文学质量及不同题材效果未执行付费评估。作者编辑后需要重新核对结构，直接记录一句作者想法也不等于生成完整方案。

重启本机API与Worker后使用新动作；生产前端已构建，没有自动重启用户正在执行的创作任务。
