# 36题材与男女频流程融入记录

日期：2026-11-13。依据用户明确要求，将既有题材设计目录接入小说写作辅助、半自动与全自动流程。

## 原有状态与本轮变化

原实现只把 `audience/genres/mechanisms` 随已采用设定传入部分上下文，没有实际装配36题材的阅读承诺、重点与专项检查，分段／整书检查也可能遗漏该设定。

本轮运行目录直接复用 `novel-ai-modules-review.html` 的设计数据，包含36题材、各题材男频／女频配置、350主题（18共同、304题材专属、28附加机制）、1,788条设计项。运行目录版本为 `2026-11-13.1`；它是可调整的设计预设，不是72种组合全部文学质量通过的声明。

## 用户可见行为

- 「故事与审阅」新增频道题材设置，选择主题材、辅题材、附加机制、作者例外及补充承诺；旧自由名称、自定义方向和机制可回填。
- 可预览未保存草稿的阅读承诺、叙事重点、检查提示、适用主题、暂不展开主题与兼容提示，预览不调用模型、不保存。
- 保存后以新的已采用reader设定生效；当前采用配置与编辑草稿分别显示。只更改频道或说明时，旧题材／机制的名称、混合自定义项及顺序保持。
- 写作页和整书入口展示本版本实际采用的配置。生成提交携带已看到的reader标识与目录版本；另一窗口修改后返回配置冲突，请刷新确认，不能悄悄换成新配置。
- 单次任务、候选与整书批次展示冻结配置及来源。未选择题材仍可手写或使用局部辅助；女频不自动增加恋爱，男频不自动增加后宫。

## 数据与执行路径

`已采用reader → assemble_profile → 队列冻结完整快照 → profile_for_action按动作展开 → 生成／审稿／修订／记忆／完结检查 → 产物与调用记录`

| 路径 | 实际接入 |
| --- | --- |
| 创意、人物、世界、大纲、卡点诊断、选区改写、情节补写 | 已采用方向、作者例外和相关主题进入当前动作上下文 |
| 半自动整书 | 继承所选工作版本的reader；作者批量情节仍是正文的主要约束 |
| 全自动整书 | 粗纲规划及后续生成使用同一冻结配置，不要求人工逐章填情节 |
| 审稿、有限修订、结构／引用纠正 | 保留原动作与冻结快照；可调偏好只作建议，不扩充作者固定checks |
| 事实提取 | 配置是创作方向，不因进入上下文而成为已发生故事事实 |
| 分段及全书检查 | 即使无常规章节context，也统一注入冻结配置与明确作者例外 |

新增接口：`GET /api/genre-catalog`、`GET /api/branches/{id}/genre-profile`、`POST /api/genre-profile/preview`。保存仍复用定义版本与故事修订CAS；主辅题材和机制采用稳定ID，并兼容旧自由文字。

任务保存目录版本、reader来源、冻结时故事版本及完整装配内容；调用元数据记录快照哈希，候选保留相同依据。目录更新不改变已经冻结的任务。更改本版本reader后，旧任务停止混用并提示按新配置新建独立批次。

历史任务缺少快照时，使用独立的 `legacy-unconfigured` 标记，保留原始已采用设定，不追套新目录主题。新增可选请求字段 `genre_profile_basis` 的缺失/null按旧请求兼容处理；同nonce真正不同的输入仍被拒绝。
