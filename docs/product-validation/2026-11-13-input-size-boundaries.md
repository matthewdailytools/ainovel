# 中文大稿输入边界实测

日期：2026-11-13。全部在临时数据库通过真实API执行，不修改日常稿件，不调用模型。测试文件`backend/tests/test_import_maximum.py`。

| 场景 | 结果 | 单次耗时 |
| --- | --- | --- |
| 20MiB+1导入 | 400明确拒绝，无部分预览持久化 | 76.60ms |
| 恰好20MiB中文/表情/扩展字稿预览 | 原字节与hash完整，UTF-16范围正确 | 893.26ms |
| 明确追加首章、跳过巨大尾部 | 回执范围准确、重试幂等 | 597.72ms |
| UTF-16章界切开代理对 | 拒绝，不写入错误正文 | 包含于用例 |
| 250000字符单章保存/读取/历史 | 正文完整；UTF-16长250002 | 保存40.41ms |
| 再增加1字符 | 422，原修订不变 | 包含于用例 |

3项测试通过2.89秒，Ruff和格式通过。20MiB预览时tracemalloc峰值189106285字节，只包括Python追踪分配，不等于进程RSS或长期内存。数字为本机一次测量，不推广为所有设备响应保证。

本用例覆盖服务端大稿边界、原件及明确范围，不证明20MiB内容在编辑器内同时渲染可用；长章浏览器交互响应仍需单独验证。此前36/100章规模与费用发送前边界见同目录长篇规模记录。
