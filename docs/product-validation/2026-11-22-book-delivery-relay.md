# 完本交付与章纲接力验收

日期 2026-11-22。按[迭代方案 P3](../../七台工作台竞品对比与迭代方案.md)验证完本六项、交付快照和自动接力的检查点。使用同一两章闸门故事的独立样本，浏览器连接构建后的前端、本机 API、Worker 和临时 SQLite。模型响应使用工程替身，预算阻断走本机预算账本，未调用付费模型。

## 完本交付

1. 依据同一版本准备简介、设定册、完整正文和仅含第一章的试读。未填验收依据的交付快照可以预览四件材料，仍可单独导出当前原稿，正式完本不通过。
2. 作者在六项中逐项填写说明，终局、人物去向、刻痕伏笔与校验各有保存稿来源。索引绑定当前章节修订，检查依据回到单项报告。逐一只省略一项作者确认，核对对应项各自阻止通过。
3. 六项全部通过后确认完本，从浏览器下载 ZIP。逐件解压并核对清单摘要、字节数及内容，试读没有包含终局。作者定稿状态另由既有入口维护。
4. 修改简介会清除沿用的交付材料核对说明。修改第二章一处文字后，旧包仍可下载。当前稿的伏笔和一致性检查待复检，不能直接确认新包。按当前保存修订重核两项，再生成新包，正文和清单包含新版本。旧包的四件材料及其清单逐字保留。

## 章纲接力

1. 从已有两章作者章纲选择连续范围，在独立版本启动。子预算不足时停在第 1 章起稿之前，记录所选章纲版本和原检查点。
2. 明确换用离线测试账户并设置续跑预算。新任务承接原批次和已冻结章纲，仍保留旧任务记录。第一章歧义需作者决定，写前核对在原情节证据上停止。此时没有正文或候选稿，直接恢复按钮不可用。
3. 作者补充本章明确不修门，原范围继续在同一续跑任务运行。两章完成后状态为阶段完成。原作品的两章正文和作者章纲逐字保持。

## 验证结果

- TypeScript 类型检查、生产构建、Ruff、Prettier 和 Git 差异检查通过。P0 写作、章纲准备、结构审阅和批次范围共七项回归，与本次两项 Chromium 验收一同通过，合计九项。收紧接力与旧流程的兼容条件后，两项短稿验收也重新通过。
- 后端全量 2,010 项、前端 382 项及既有 Node 检查 48 项通过。后端全量保留一次 Starlette TestClient 的既有弃用提示。
- 从实际浏览器下载文件并逐件解压核对 SHA-256。320px、200% 根字号下，交付面板没有导致页面横向溢出。实看截图可找到六项入口、历史快照和下载按钮。
- 将 SQLite 备份恢复到独立目录并重新启动 API 后，已确认的历史 ZIP 字节一致，恢复后的当前保存稿仍可单独导出。有前文改动时，旧的局部检查保留展示，受影响的后续章节须补当前稿的复核依据。旧自动批次或半自动批次附带的章纲需由作者核对固定条件并明确保存后才能接力。
- 初轮核对发现只有草稿的设定尚未纳入设定册，夹具改为明确确认设定后复验。正文长度和修订可验证起稿完成，工程替身的语义输出不能作创作品质验收。
