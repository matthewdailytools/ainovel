# 写作页章纲、设定原文与单项校验验收

日期 2026-11-22。按[迭代方案 P0](../../七台工作台竞品对比与迭代方案.md)验证 M4、M5、M6 的章级交接。通过无头 Chromium 访问构建后的前端、本机 API、临时 SQLite 和实际 Worker，模型响应使用确定性工程替身。用例只操作新建的原创工程样本，未读写日常作品或调用付费模型。

## 相邻两章

1. 在第一章保存作者章纲，再用键盘折叠和展开。章纲安排只留下青石来历伏笔，正文修订不变。选中末句生成候选，采纳前首稿逐字保留，显式采纳后只替换该句。
2. 第二章显示暂无章纲，直接手写添加一句并保存。展开设定并定位第一章石碑禁令，共两步。核对设定条目、来源修订、上下文和高亮原文，当前章节和正文光标保留。
3. 第二章创建两项检查。一项使用已采用的世界规则和第一章，核对两章的寿元扣减数值。另一项仅核对第二章打开竹匣的时点，两项初次结果均为符合要求。替身检查复检请求的资料范围，分别返回对应章节的逐字证据。
4. 将第一章扣减从十年改为十二年。回到第二章后，仅跨章项提示「已过期 · 上一章正文有变动」。仍可打开旧检查引文。另有根据第一章正文整理的石碑禁令提示原文依据待核对，定位后仍显示被引用的历史修订及其高亮。
5. 用键盘启动跨章项复检。新结果为发现问题，显示第一章十二年与第二章十年，历史中仍保留最初的十年引文。另一项报告内容及版本不变，两份稿件内容与修订均按作者最后保存的结果保留。
6. 调整到 320px 视口并将页面根字号放大至 200%，核对无页面横向溢出、章节仍可切换。另开一个独立全自动两章工作批次，逐章比较写作页显示的冻结 AI 章纲与写前准备回执。

## 验证结果

- Node.js 24.22.3 下的 TypeScript 类型检查与生产构建通过。Chromium 共通过 6 个用例，包含本次相邻两章与冻结章纲两项，以及手动反馈修订、全自动章纲准备两个分支、双窗口保存冲突。
- 全量后端 1983 项通过，其中 7 个新增用例覆盖章纲并发保存、冻结来源、旧修订定位、同章与跨章依赖、运行中改稿、邻章变化及失效设定。前端 382 项及旧版 48 项通过。OpenAPI 重生成一致，Ruff、Prettier 和 Git 差异检查通过。
- 实际查看 320px、200% 字号的测试截图。来源高亮、校验引文与历史报告可读。初次试跑出现 Windows 浏览器连接关闭提示，随后一次回归曾在按钮启用前尝试聚焦。调整断言等待按钮可用后，六例复测通过。

复现命令为 `npm run build` 后执行 `npm run test:e2e -- tests/e2e/chapter-workbench.offline.spec.ts`。断言与测试入口见[浏览器用例](../../tests/e2e/chapter-workbench.offline.spec.ts)和[离线 Worker 替身](../../scripts/e2e_server.py)。该样本验证章纲、版本、来源、复检和手写入口。模型质量、作者用时收益与其他作品的实际使用效果仍需单独验证。
