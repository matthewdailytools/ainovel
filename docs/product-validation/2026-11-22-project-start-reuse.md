# 可选立项、旧稿导入与手法复用验收

日期 2026-11-22。按[迭代方案 P2](../../七台工作台竞品对比与迭代方案.md)验证从一句话到手写，再到可选立项、旧稿拆分和章级手法引用。样本使用一个自拟 TXT 文件和一个独立工程验证作品。浏览器连接真实前端、API、临时 SQLite 和 Worker。再次拆解和写作建议使用工程模型替身。

## 验收路径

1. 直接采用一句想法，进入写作并保存首章和作者章纲。随后另开可选的立项简报，保存草稿。刷新后从「继续上次立项草稿」取回预定结局和最后一镜。确认简报时沿用默认的创作约定选项，核对原方向与首章修订。
2. 上传旧稿，先查预览，确认此时只有原作者章。跳过卷首，合并一处把正文内抬头误识别为新章的分段，分别编辑标题并调整追加顺序。保存章界草稿后刷新，核对恢复的标题和顺序，再确认导入。
3. 对照回执中的源文件 SHA-256、原始 UTF-16 选段、导入章节 ID、章序和正文修订。确认后的两个新章逐字匹配旧稿选段，既有首章、章纲和正文保持。
4. 将同一份 TXT 作为资料书入库，与旧稿回执核对文件摘要。在参考工作区保存第一张手法卡，标明可迁移写法、需要替换的细节和逐字来源。定位原文，明确引用到作者首章。
5. 再次拆解后编辑并保存第二版资料卡。核对旧章的卡片仍绑定旧修订及第一条原文。另一章需显式引用才获得新卡，定位后分别高亮当时原文，两处都保留源文件指纹和范围。
6. 两章的手法默认未选用。作者明确勾选首章旧卡后发起写作建议，请求只包含所选固定引用的 ID，Worker 成功完成。切换另一章后，其卡片仍未勾选，两份保存稿保持。

## 验证结果

- Node.js 24.22.3 下的 TypeScript 类型检查与生产构建通过。最终 12 项 Chromium 用例通过，包括 P2 一体化场景及 P0、P1、快速构思、旧稿导入和参考工作区回归。首轮一体化用例曾因选择器严格匹配未定位目标章节下拉框，按控件角色定位后复测通过。
- 全量后端 1996 项通过。另单独复跑了 25 项相关用例，覆盖旧稿回执、简报同步竞态、手法重复引用与单项发送范围。Worker 用例验证已固定的引文留在本机，模型请求只额外携带明确选中的手法说明。前端 382 项和旧版 48 项通过。OpenAPI 重生成一致，Ruff、Prettier 和 Git 差异检查通过。
- 320px、200% 根字号下无页面横向溢出，实看截图中的手法卡、文件摘要与高亮原文可读。范围定位与引用寿命已验证，付费模型效果和长期创作收益留待实际使用观察。
