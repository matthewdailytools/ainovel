# 跨章设定与伏笔台账验收

日期 2026-11-22。使用四个相邻原创章节验证[迭代方案 P1](../../七台工作台竞品对比与迭代方案.md)。Chromium 连接构建后的前端、本机 API 和临时 SQLite。样本只含工程验收数据，台账和复检均由作者操作，本用例没有创建 AI 任务。

## 验收路径

1. 新建设定生效计划，选用已保存的青灯渡规。计划显示未登记正文证据。选中第一章原文登记后，该阶段显示已核对。
2. 新建半片铜叶伏笔，关联第二、三章。分别登记第一章埋设和第二章推进，连同原文中的扩展字符一起核对位置。第三章处于原回收窗口且已有保存稿，今日条可用键盘定位第三章和回收阶段。登记证据后提示消失。另一个没有计划窗口的旧伏笔始终没有到期提示。
3. 修改第二章的刻痕描述。只产生一项推进待复检，影响列表显示来源章和明确登记的关联章。可从影响列表跳第三章，再用今日条回到第二章，重新选中并核对。埋设、回收和已登记的设定依据仍按各自的证据判断。
4. 将回收窗口改到尚无保存稿的第四章。第三章的历史证明仍可查看，旧窗口的到期入口消失。用旧选区提交返回 409，当前台账和正文保持。第四章保存稿进入窗口后，使用新选区复检，回收证明绑定第四章，第三章旧引文与原窗口保存在历史。
5. 从第四章点击推进项的正文定位，返回第二章并选中最新的逐字证据。再修改第一章的渡规表述，只复检设定生效项。同章引用旧稿的埋设项仍待复检，其他章节的推进与回收保持。

## 验证结果

- Node.js 24.22.3 下的类型检查和生产构建通过。Chromium 共通过 7 项，覆盖四章台账场景与 P0、章纲准备、反馈修订和双窗口保存冲突回归。今日条跳转后，目标阶段获得键盘焦点。计划外复检返回 409，测试作品的模型任务数为零。
- 320px、200% 根字号下无页面横向溢出。实看窄屏截图，今日条的按钮与台账操作可读，章节目录沿用横向滚动。
- 全量后端 1990 项通过。另单独复跑了 35 项相关用例，其中 7 项台账回归覆盖无窗口、窗口归档和重排、旧稿取证、重复请求、并发依据和已有图谱记录。前端 382 项和旧版 48 项通过。OpenAPI 重生成一致，Ruff、Prettier 与 Git 差异检查通过。

复现命令为 `npm run build` 后执行 `npm run test:e2e -- tests/e2e/story-ledger.offline.spec.ts`。详见[浏览器用例](../../tests/e2e/story-ledger.offline.spec.ts)。本次样本覆盖作者确认和复检流程。不同作品的使用收益与文学判断仍需单独验证。
