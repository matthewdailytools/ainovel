# 写作与设定工作区验收

日期 2026-11-22。以两章原创新稿为样本，使用构建后的前端、Chromium、本机 API、临时 SQLite 和 Worker。对话由离线模型替身返回，样本与日常作品及付费账户隔离。

## 写作、设定与对话

1. 在左侧分卷管理中以第二章为起始章创建一卷。验收重新打开后仍有这卷，原目录顺序与正文修订一致。分卷是目录范围，起始章归档后可恢复该章或重新指定起点。
2. 用键盘打开第二章，从章尾切到世界设定。中间可读写当前工作版本已采用的设定。保存后用同一路径读出已采用文本。回到第二章，光标和编辑器滚动仍在原处。
3. 在右栏选择回复长度，在世界设定下发起两轮对话。第二轮收到同一设定的前一轮。切到第二章后，设定会话仍可回查，章稿会话从自己的第一轮开始。核对第二章正文与修订保持原值。
4. 在第二章移动光标、填写「下次从这里继续」，立即刷新。已恢复第二章、光标、滚动位置、便笺和该章会话。浏览器位置缓存绑定章稿修订与工作版本。模拟先前的服务器写入晚到时，更新的本地位置仍可恢复，其他窗口写入的不同位置优先使用服务器记录。
5. 在设定留下草稿时从树中切换，取消后草稿仍在。模拟另一窗口先采用新设定，当前草稿保持原文并显示最新依据。作者核对后明确选择以新版本为保存基础，才能采用自己的稿子。

## 工程检查

- 1440px 与 320px、200% 根字号分别检查了三栏及窄屏重排。章节树和设定入口支持键盘操作；核对桌面正文滚动、右栏上下文和窄屏横向溢出。
- 备份恢复用例核对分卷结构与正文顺序，前版本 SQLite 初始化后可读写分卷。对话后端覆盖版本变更、跨目标边界、重复提交、取消和预算拒绝。
- 后端全量 2,020 项、前端 385 项及既有 Node 检查 48 项通过。OpenAPI 生成、TypeScript 检查、生产构建、Ruff、Prettier 和 Git 差异检查通过。
- Chromium 共覆盖 19 个场景。首轮跨章台账用例发现「今日条」跳转和测试补点折叠控件有时序冲突。已保存章节现在直接展开目标，测试同步等待目标展开。修正后的构建重跑 7 个相关场景，全部通过。
