# 豆包 Skill 本地交接

## 现在可以用

在具备自定义技能和本地文件权限的豆包桌面工作模式中，上传 ZIP 或按客户端的自定义技能入口导入 [SKILL.md](ainovel-file-handoff/SKILL.md)。ZIP 根目录为 `SKILL.md`。Windows PowerShell 下可在本目录运行 `Compress-Archive -Path ./ainovel-file-handoff/SKILL.md -DestinationPath ./ainovel-file-handoff.zip` 重新打包。 [豆包官方技能打包说明](https://open.doubao.com/document/doubao-developer-guide/skill-integration-guide) · [飞书官方豆包工作介绍](https://www.feishu.cn/content/article/7677519271848610746)

默认交接根目录为 `%USERPROFILE%\ainovel-handoff`，也可以由作者指定。本机首次试用可以在豆包中说：

> 使用小说工作台文件交接技能。作品名《渡口来信》，在默认交接目录下写一章 UTF-8 Markdown，文件名「第12章.md」。沈砚把封好的信交给林青，林青收下但没拆。先用原创样稿验证文件能否写出。

作者随后在工作台选定作品，通过「写作」现有 TXT／Markdown 导入创建新章。修改已有章、局部改写和设定、大纲等文本，通过复制回相应编辑字段保存。文件无须提交来源标记，作者手写、AI 生成和作者改过的稿件使用同一条作者输入流程。交接只使用文件和现有编辑界面，无需 MCP。交接目录属于作者的本地文件。交给豆包处理的材料仍按豆包客户端的服务设置处理，请只选这次需要的内容。 [豆包隐私政策](https://www.doubao.com/legal/privacy)

## 后续工作台功能

在[七台工作流](../../七台创作工作流设计.md)逐步落地时，每个可由作者填写或改写的创作入口都对应一个适用的豆包 Skill。当前先交付一个可安装技能，内含下表各步骤。后续把各入口对应的任务细化为可单独安装和调用的 Skill，共用同一文件约定，由工作台为当前入口给出相应 Skill、可用导出范围和回填位置。

| 工作台 | 对应 Skill | 作者可以交回的内容 |
| --- | --- | --- |
| M1 立项 | 立项起草、立项修订 | 创作思路、立项字段、锁定或待定事项 |
| M2 拆解 | 拆解目标整理、手法卡编辑与重拆 | 拆解范围和问题、手法卡内容、引用位置 |
| M3 设定 | 设定起草与补充、设定修订 | 人物、世界规则、关系、事件、时间线、作者冲突处理意见 |
| M4 大纲 | 四级大纲起草与修订、设定及伏笔计划编辑 | 总纲、卷纲、单元纲、章纲、台账计划与章级情节 |
| M5 写作 | 写作要求整理、新章／续写、选区改写、整章修订 | 逐章情节、正文、替换段落、作者反馈 |
| M6 校验 | 校验范围与反馈整理、正文／设定修订、复检要求整理 | 作者问题、修改后的正文或设定、复检条件 |
| M7 完本 | 完本核对意见整理、交付文案起草与修订 | 核对意见、简介、试读、设定册和交付说明 |

第一步在作品和作者输入入口提供相应 Skill、案例与交接目录提示，沿用现有导入和编辑流程。后续按需要补充「导出本次输入」和「从文件填入当前编辑区」。作者选文件、确认目标及保存动作，沿用所在工作台的版本和原稿保护。新章导入仍创建新章；已有正文先填入编辑区，保存前按现有规则处理覆盖和版本冲突。文本交接也不代替 M6 的复检和 M7 的完本判定。

验收时至少覆盖以下场景：

1. 豆包写出一份中文 UTF-8 正文，作者沿现有入口导入新章、手改、保存，重开作品后仍看到修改。AI 原始稿、作者修改过的稿和手写稿按同样的路径操作。
2. 作者把已有章的局部改写回填至目标选区，同名输出保留旧文件，作者可以在正常历史中找到旧稿。
3. 从每个实际开放的作者输入或修改入口都能找到对应 Skill 和回填位置。交回文本后沿用该字段的现有确认、版本和下游生效规则。
4. 客户端无本地权限时能给出可复制结果，实际保存或导入完成后才提示成功。
